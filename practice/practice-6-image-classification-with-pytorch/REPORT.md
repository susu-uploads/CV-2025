## Архитектура модели

В качестве базовой модели используется собственная сверточная нейронная сеть `FurnitureCNN`, построенная по схеме методического примера.

Архитектура модели:

- `Conv2d(3 -> 10, kernel_size=3, padding=1)`
- `ReLU`
- `Conv2d(10 -> 10, kernel_size=3, padding=1)`
- `ReLU`
- `MaxPool2d(2)`
- `Conv2d(10 -> 10, kernel_size=3, padding=1)`
- `ReLU`
- `Conv2d(10 -> 10, kernel_size=3, padding=1)`
- `ReLU`
- `MaxPool2d(2)`
- `Flatten`
- `Linear(... -> 5)`

Первые сверточные слои выделяют локальные признаки изображения: контуры, границы, текстуры и простые формы. После двух операций `MaxPool2d` пространственный размер уменьшается, а затем признаки разворачиваются в вектор и передаются в полносвязный классификатор.

Структура модели дополнительно проверяется через `torchinfo.summary`.

## Теория

1. **Зачем разделять работу на два notebook?** Один notebook отвечает за подготовку данных, второй — за обучение модели. Это упрощает повторные эксперименты и делает структуру решения более понятной.

2. **Почему датасет сохраняется в `.data`?** Это локальный каталог практики для исходных и подготовленных данных. Такой подход делает работу самодостаточной внутри своей папки.

3. **Зачем перепаковывать датасет?** После перепаковки данные лежат в стандартной структуре `train / validation / test`, и их можно сразу читать через `ImageFolder` без собственного класса датасета.

4. **Что делает `ImageFolder`?** `ImageFolder` воспринимает названия подкаталогов как классы и автоматически строит пары `(изображение, метка)`.

5. **Почему изображения приводятся к размеру `128x128`?** Все изображения в batch должны иметь одинаковую форму, иначе `DataLoader` не сможет собрать их в один тензор.

6. **Что делает `ToTensor()`?** Преобразует изображение `PIL.Image` в тензор PyTorch формы `(C, H, W)` и переводит значения пикселей в диапазон `0..1`.

7. **Что делает `Conv2d`?** Сверточный слой ищет локальные признаки изображения: границы, текстуры, цветовые переходы и простые формы.

8. **Что означают `in_channels`, `out_channels`, `kernel_size`, `stride`, `padding`?**
- `in_channels` — число входных каналов;
- `out_channels` — число карт признаков, которые строит слой;
- `kernel_size` — размер окна свертки;
- `stride` — шаг перемещения окна;
- `padding` — рамка по краям изображения.

9. **Зачем нужна `ReLU`?** Она добавляет нелинейность. Без нее несколько сверточных слоев свелись бы к одной линейной операции.

10. **Что делает `MaxPool2d`?** Уменьшает ширину и высоту карт признаков и оставляет наиболее сильные отклики внутри локального окна.

11. **Зачем нужен `Flatten`?** После сверточной части признаки имеют многомерную форму. `Flatten` разворачивает их в вектор перед полносвязным слоем.

12. **Почему используется `Linear`?** Полносвязный слой переводит извлеченные признаки в logits классов и завершает классификацию.

13. **Почему выбрана `CrossEntropyLoss`?** Это стандартная функция потерь для многоклассовой классификации, когда метки заданы индексами классов.

14. **Почему выбран `Adam`?** Это удобный базовый оптимизатор, который хорошо работает без сложной настройки.

15. **Что такое `TrivialAugmentWide`?** Это встроенная аугментация из `torchvision`, которая случайно выбирает одно преобразование изображения и его интенсивность.

16. **Зачем аугментация применяется только к train?** `Validation` и `test` нужны для честной проверки на обычных изображениях, без случайных искажений.

17. **Зачем нужна матрица ошибок?** Она показывает, какие пары классов модель чаще всего путает между собой, а не только общую точность.
